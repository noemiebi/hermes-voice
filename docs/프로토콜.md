# hermes-voice 서버·클라이언트 계약 (0단계)

서버: Python 3.12, FastAPI + uvicorn, `127.0.0.1:8480`. 정적 파일 `web/`를 `/`에서 서빙하고, WebSocket은 `/ws`. 아이폰은 tailscale serve `https://<tailscale-host>:8464` → `http://127.0.0.1:8480`.

## WebSocket `/ws`

연결 하나 = 음성 대화 하나. 서버는 연결마다 헤르메스 세션 id를 유지한다(재연결 시 클라이언트가 `resume`으로 돌려줄 수 있음).

### 접속 토큰 (선택, 2026-11-03 v42 / 앱 0.6.0)

Tailscale 밖에 띄울 때를 위한 선택적 인증. `.env`의 `VOICE_TOKEN`이 비어 있으면 인증 없음(이전과 같음).

- 설정돼 있으면 연결 뒤 **첫 메시지**가 `{"type":"hello",...,"token":"<VOICE_TOKEN>"}`이어야 한다. 서버는 `hmac.compare_digest`로 비교한다(`VoiceSession._authenticate`).
- 토큰이 틀리거나 없거나, 첫 메시지가 `hello`가 아니면(바이너리·JSON 아님 포함) 서버는 `{"type":"error","code":"unauthorized","message":"접속 토큰이 틀립니다"}`를 보내고 **close code 4401**로 닫는다. 서버 로그: `hello 거부: 토큰 불일치 (<client ip>)` (WARNING).
- 통과한 `hello`는 평소대로 처리된다(`ready` → `history` → `status`). 이후 메시지는 토큰 검사 없음.
- `/health`는 인증 없이 열려 있되, `VOICE_TOKEN`이 설정되면 `{"ok": bool}`만 준다(STT·TTS·헤르메스 내부 정보 숨김). 토큰이 없으면 전체 정보 그대로.
- 클라이언트: 토큰은 localStorage `hv.token`. 앱 시작 때 주소에 `?token=...` 또는 `#token=...`이 있으면 저장하고 `history.replaceState`로 주소에서 지운다(아이폰 설치 흐름: `https://<host>/?token=<값>` 링크를 Safari에서 한 번 열고 → 공유 → 홈 화면에 추가. 홈 화면 앱 주소에는 토큰이 남지 않는다; 빈 값 `?token=`이면 저장된 토큰을 지운다). 토큰이 있으면 `hello`에 `token`을 싣는다.
- 클라이언트는 `unauthorized` 에러나 close 4401을 받으면 자동 재연결을 멈추고(`st.authFail`), 대화를 끄고, 설정 시트를 열어 "접속 토큰" 칸에 초점을 주며 상태줄에 "접속 토큰이 필요합니다", 연결 표시에 "토큰 필요"를 띄운다. 토큰을 저장하면(빈 칸으로 저장하면 지움) 즉시 다시 접속한다.

### Origin 검사

WebSocket에는 CORS가 적용되지 않는다. 토큰 없이 띄우면 같은 기기의 브라우저에서 연 아무 웹페이지가 `ws://127.0.0.1:8480/ws`에 붙어 `text`로 헤르메스(도구 포함)에 명령을 넣을 수 있으므로, 서버는 `ws.accept()` **전에** `Origin` 헤더를 본다(`server/app.py` `_origin_allowed`). 토큰 검사와 별개로 항상 적용된다.

- `Origin` 헤더가 없으면 허용(브라우저가 아닌 클라이언트: e2e 테스트, 스크립트).
- `Origin`의 host[:port]가 요청의 `Host`(또는 `X-Forwarded-Host`, 쉼표로 여러 개면 그중 하나)와 같으면 허용(같은 출처). 대소문자 무시, 기본 포트(http 80, https 443)는 떼고 비교. 예: 아이폰이 tailscale serve 주소로 열면 `Origin: https://<ts-host>:8464`, `Host: <ts-host>:8464`.
- `VOICE_ALLOWED_ORIGINS`(쉼표 구분)에 든 값과 정확히 같거나(끝 `/` 무시), 그 목록에 `*`가 있으면 허용.
- 그 외(`Origin: null` 포함)는 accept 전에 close(4403) → 클라이언트는 **핸드셰이크 HTTP 403**을 받는다(uvicorn 실측; Starlette TestClient에서는 close code 4403으로 보임). 서버 로그: `ws 거부: origin <origin> (host <host>)` (WARNING).

### 클라이언트 → 서버

- **바이너리 프레임**: 마이크 PCM, int16 LE, mono, **16000 Hz**. `start_utterance` 뒤 `end_utterance` 전까지만 보낸다.
- **텍스트(JSON)**:
  - `{"type":"hello","resume":"<session_id>|null","client":"pwa","token":"<선택>"}` 연결 직후 1회. `token`은 서버에 `VOICE_TOKEN`이 설정됐을 때만 필요(위 "접속 토큰"). (2026-11-03, v39) `resume`이 없거나 비면 서버가 기억하는 **마지막 세션**(`history.json`의 `last_session`)을 이어 쓰고, 그것도 없을 때만 새 id를 만든다(iOS가 홈화면 앱의 localStorage를 지워 `resume`이 빠지는 일 대책). 정해진 세션은 마지막 세션으로 기록하고, `ready` 다음에 `history`를 보낸다. 서버 로그: `hello resume=<앞 8자|없음> -> <sid 앞 8자> (history N개)`.
  - `{"type":"start_utterance"}` 누르기 시작(또는 VAD 시작).
  - `{"type":"end_utterance"}` 손 뗌 → 서버가 STT 실행.
  - `{"type":"interrupt"}` 재생·생각 중단(끼어들기, 정지 버튼).
  - `{"type":"set_model","model":"voice-fast"|"voice-deep"}` 기본 `voice-fast`. 서버는 확인으로 `ready`를 다시 보낸다.
  - `{"type":"text","text":"..."}` 타이핑 입력(시험용, STT 건너뜀).
  - `{"type":"new_session"}` 헤르메스 세션 새로 시작. 서버는 새 `session_id`가 담긴 `ready`를 보낸다. 새 id는 서버의 마지막 세션이 된다.
  - `{"type":"log","item":{"r":"user"|"bot"|"sys","t":"...","at":<ms>}}` (2026-11-03, v39) 화면 기록 한 줄. 클라이언트가 `hv.log`에 저장할 때마다 보낸다(연결이 닫혀 있으면 생략, 나중에 다시 보내지 않음). 서버는 현재 세션 기록에 덧붙이고 응답하지 않는다. `r`이 셋 중 하나가 아니거나 `t`가 빈 문자열이면 무시.
  - `{"type":"diag","text":"..."}` (2026-11-03, v37) 진단 전용. 클라이언트 콘솔 진단 줄([mic]·[audio]·[ws]·[conv])을 그대로 보낸다. 서버는 응답하지 않고 로그에 `client: <text 앞 400자>`로만 남긴다(text가 문자열이 아니면 무시). 연결이 끊긴 동안의 최근 20줄은 재연결 때 `hello` 다음에 순서대로 보낸다.

`text` 입력일 때 서버는 `transcript`를 보내지 않는다(클라이언트가 자기 자막을 직접 붙임).

### 서버 → 클라이언트

- **바이너리 프레임**: TTS PCM. 앞 4바이트 uint32 LE = `generation`, 그 뒤 int16 LE mono **44100 Hz**(Supertonic 기본). 클라이언트는 현재 `generation`과 다른 프레임을 버린다(끼어들기 뒤 늦게 온 오디오 방지).
- **텍스트(JSON)**:
  - `{"type":"ready","session_id":"...","model":"voice-fast","out_sample_rate":44100}`
  - `{"type":"history","session_id":"...","items":[{"r","t","at"}]}` (2026-11-03, v39) `hello` 처리 때 `ready` 바로 다음에 1회(기록이 비어도 보냄). 서버가 보존한 그 세션의 화면 기록. 클라이언트는 items가 1개 이상이면 서버를 정본으로 화면·`hv.log`를 덮어쓰고(같은 내용이면 다시 그리지 않음), 비어 있고 로컬 기록이 있으면 로컬을 유지한 채 로컬 항목을 `log`로 한 번 올린다.
  - `{"type":"status","state":"idle"|"listening"|"transcribing"|"thinking"|"speaking"}`
  - `{"type":"transcript","text":"...","ms":412}` STT 결과(최종).
  - `{"type":"assistant_delta","text":"..."}` 헤르메스 토큰 스트림(자막용).
  - `{"type":"assistant_done","text":"<전체 답>"}`
  - `{"type":"tool","name":"...","state":"started"|"completed"}`
  - `{"type":"speak_start","generation":n,"text":"<이 구간에서 읽는 문장>"}` 바이너리 오디오 직전.
  - `{"type":"speak_end","generation":n}` 해당 generation의 마지막 오디오 뒤.
  - `{"type":"error","message":"..."}`
  - `{"type":"error","code":"unauthorized","message":"접속 토큰이 틀립니다"}` 토큰 거부. 바로 뒤 close code 4401.

### 서버 턴 흐름

1. `end_utterance` → 모은 PCM을 mlx-whisper(ko)로 받아쓰기 → `transcript`. 빈 결과·환각(짧은 "감사합니다" 류)은 버리고 `status: idle`.
2. 헤르메스 `/v1/chat/completions` (stream, `model` = 현재 route, 헤더 `X-Hermes-Session-Id`)로 전송. 시스템 지시는 음성용 한국어 노트(짧은 구어체 문장, 마크다운·목록·URL 금지, 도구 결과를 확인하기 전에 성공했다고 말하지 말 것).
3. 토큰을 문장 분할기에 넣어 문장이 완성될 때마다 TTS 큐로. 첫 문장이 나오기 전에 `hermes.tool.progress`(도구 시작) 이벤트가 오면 "잠깐 확인해 볼게요." 같은 짧은 말을 먼저 읽는다(턴당 1회).
4. TTS는 문장 단위로 합성(기본 Supertonic 3, 선택 Qwen3-TTS 스트리밍 + Supertonic 폴백, 아래 'TTS 엔진') → `speak_start` + 바이너리 PCM(약 0.5초 단위로 쪼개 전송) → 마지막에 `speak_end`.
5. `interrupt`가 오면 `generation`을 올리고, TTS 큐 비우고, 헤르메스 스트림 연결을 끊는다.

**TTS 독음 정규화** (`server/tts_text.py` `normalize_for_tts`, 2026-11-02). Supertonic이 "ko" 고정이라 영어·기호·숫자 표기가 어색하게 읽히는 문제의 대책으로, `_speaker`가 `tts.synth` 직전에 문장마다 적용한다(`speak_start.text`·`heard`·에코 메모리는 원문 유지, 결과가 비면 합성 생략, 바뀐 경우 `session` DEBUG 로그 `독음: 원문 -> 결과`). 순서: 마크다운·이모지 제거, URL→"링크", 이메일→"로컬 골뱅이 도메인 점 컴", 파일 확장자→" 점 파이/엠디/제이슨/웨이브…" → 숫자(천 단위 쉼표 제거, `HH:MM`→"H시 M분", `YYYY-MM-DD`/`YYYY.MM.DD`→"YYYY년 M월 D일", `a/b`는 한 자리/한 자리이고 분자<분모면 "b분의 a", 아니면 유효한 월/일이면 "M월 D일", `3.5`→"3점 5", 전화번호 붙임표 제거, 숫자 사이 `~ - –`→"에서", `16:9`→"16 대 9", `$`·`₩`·`℃`·단위 몇 개, 끝으로 횟수·개수 단위 앞 숫자는 고유어 수사로) → 사전(`server/tts_lexicon.tsv` + 사용자 `TTS_LEXICON_USER`, 대소문자 무시·영문 단어 경계·긴 것부터, 사용자 우선) → 사전에 없는 2~6글자 대문자 약어와 한 글자 대문자는 글자별 읽기 → 그 밖 영어 단어는 `TTS_ENGLISH_MODE=keep`이면 그대로, `spell`이면 글자별 → 기호(`%`→퍼센트, `&`→앤드, 숫자 사이 `+`→플러스, `=`→는, 화살표·`·`→쉼표, 단어 사이 `/`→"또는", 따옴표·괄호·별표·꺾쇠 제거). 숫자 자체는 한글로 바꾸지 않는다(엔진이 읽음). 예외로 횟수·개수 단위 앞 숫자는 고유어 수사로 바꾼다(2026-11-03, `_native_counters`: 1~99 + 번·번째·개·명·살·시·시간·마리·잔·장·권·대·병·벌·켤레·송이·그루·채·척·통·가지·군데·곳·달·사람·판·끼·알·줄·자루·포기·조각 → "네 번", "스무 개", "첫 번째"; `HH:MM`과 "N시"(뒤에 에·까지·부터·쯤·경·반·정각·분·공백·문장 끝일 때만)는 "열한 시 10분"처럼 시만 고유어. 그대로 두는 것: 100 이상, 0으로 시작, 앞에 제·No.·#·소수점, "번" 뒤 버스·출구·번호·문제·길 등이나 `:` `.` `)`, "개월/개국/개년", "3장 1절", "2대 사건"·"20대"·"1대1", "달러", 분·초·년·월·일·층·호·쪽·세 등 한자어 단위). 스타일 노트에는 독음 지시를 넣지 않는다(넣었더니 헤르메스가 자막까지 "지메일"·"피디에프"처럼 한글로 써서 2026-11-02 제거). 화면 글자는 원문, 소리만 독음.


## 양방향(핸즈프리) 모드 — 1단계 (2026-11-02 추가)

기본 모드. "대화 시작"을 누르면 끝낼 때까지 마이크가 계속 열려 있고, 서버가 VAD로 말의 시작·끝을 잡는다. 누르고 말하기는 설정에서 고를 수 있는 보조 모드로 남긴다.

### 클라이언트 → 서버 (추가)

- `{"type":"conversation","on":true}` 핸즈프리 시작. 이후 클라이언트는 `start_utterance`/`end_utterance` 없이 **바이너리 PCM(16 kHz int16)을 계속** 보낸다(약 100 ms 단위). `{"type":"conversation","on":false}`로 끝내면 전송을 멈추고 서버는 진행 중인 턴을 정리한다.
- **사전 버퍼(v45 / app 0.6.3).** 구체를 탭한 뒤 마이크 준비(`getUserMedia`·워클릿 로드, 홈 화면 앱은 권한 프롬프트까지)가 끝나기 전에 말을 시작하면 첫 음절이 사라지던 문제 대응. 워클릿은 캡처 그래프가 붙자마자(`processorOptions.prebuf`) 프레임을 내고, 대화가 꺼져 있는 동안 클라이언트는 이를 **서버로 보내지 않고** 최근 `PREBUF_MS`(2000 ms)만 링 버퍼에 보관한다(탭 이전 프레임은 시작 때 비움). 구체 탭으로 새로 시작할 때만 `conversation on` 직후 앞쪽의 전부 0인 프레임을 버리고 보관분을 한꺼번에 먼저 보낸 뒤 실시간 프레임을 잇는다(워클릿은 이미 내보내는 중이면 `start`에서 다운샘플러를 reset하지 않아 경계가 이어짐). 재연결·새 세션처럼 `conversation on`을 다시 보내는 경로와 누르고 말하기에서는 보관분을 버린다. 로그 `[conv] 사전 버퍼 N ms 전송(탭→준비 완료 M ms)`(M = 탭부터 `conversation on` 전송까지).
- **준비 완료 알림음(v46 / app 0.6.4).** 구체 탭부터 첫 마이크 프레임(워클릿 `level` 보고, 0 샘플 포함)까지가 300 ms를 넘으면(첫 대화의 `getUserMedia`·권한 창) 준비 완료 때 짧은 상승 2음(523→784 Hz, 각 45 ms; 알아들었을 때의 660→880 Hz와 구별)을 낸다. 트랙 재사용(300 ms 이하)이거나 설정 '알림음'·소리 끔이면 소리 없음. 준비 중에는 구체 `data-state="starting"`, 상태줄 "마이크 준비 중…". 로그 `[conv] 준비 완료 M ms(알림음 Y/N)`(3초 안에 프레임이 없으면 `준비 완료 미확인` 경고 뒤 표시만 거둠).
- `{"type":"playback","state":"speaking"|"idle","generation":n}` 클라이언트 스피커 상태. 재생 큐에 오디오가 들어가 소리가 나기 시작하면 `speaking`, 큐가 다 비면 `idle`. 서버는 이걸로 "지금 내 목소리가 스피커에서 나오는 중"을 알고 끼어들기 판정을 엄격하게 한다(에코 오탐 방지).
  - (2026-11-02, v18) 추가 필드 `pos_ms`: 이 generation에서 지금까지 스피커로 실제 나간 오디오 길이(ms) = 끝난 소스 길이 합 + 지금 소스의 `ctx.currentTime - 시작 시각`(아무것도 시작 전이면 음수일 수 있음, hold로 끊긴 소스는 끊긴 지점까지). generation이 바뀌면 0부터. `out_latency_ms`: `AudioContext.outputLatency`를 지원하면 그 값(ms). 클라이언트는 `speaking` 동안 **250 ms마다** `{"type":"playback","state":"speaking","generation":g,"pos_ms":p,"out_latency_ms":l}`를 다시 보내고, hold 중에는 보내지 않는다(위치 고정), resume 뒤 다시 보낸다. 두 필드는 선택이며 없는 옛 메시지도 그대로 받는다(그때는 에코 대조 감지기를 쓰지 않음).
- `{"type":"settings","aec":true|false,"half_duplex":true|false}` 클라이언트 설정 알림. `half_duplex`가 true면 클라이언트는 재생 중 마이크 프레임을 보내지 않는다(에코 캔슬이 안 되는 환경용 보조책).

### 서버 → 클라이언트 (추가)

- `{"type":"vad","speech":true|false}` 서버 VAD가 말 시작/끝을 잡았을 때(화면 표시용).
- `{"type":"interrupt","generation":n}` 서버가 끼어들기를 판정해 재생을 끊었을 때. `n`은 **새** generation(끊긴 것 + 1)이다. 클라이언트는 재생 큐를 비우고 현재 generation을 `n`으로 바꾼다. 클라이언트가 보낸 `interrupt`에도 같은 메시지로 답한다.
- `status`의 `state`에 `"waiting"`(핸즈프리에서 말을 기다리는 중) 추가. 흐름: waiting → listening(말하는 중) → transcribing → thinking → speaking → waiting. (2026-11-02 에코 대책) 문장 사이에 다음 문장이 늦으면 speaking → thinking → speaking으로 오갈 수 있고, 잠정 끼어들기 중에는 speaking → listening(→ transcribing) → speaking(resume) 또는 → listening/thinking(확정)으로 간다.
- `{"type":"hold","generation":g}` (2026-11-02) **잠정 끼어들기**. 클라이언트는 g의 재생을 즉시 멈추되 아직 안 들려준 오디오를 버리지 않고 보관하고, hold 중 들어오는 g의 오디오 청크도 재생하지 않고 보관한다. hold에 대해서는 `playback` 메시지를 보내지 않는다. generation은 바뀌지 않는다.
  - (2026-11-02, v19) `{"type":"hold","generation":g,"mode":"duck","gain":0.2}` **덕킹 hold**(서버 기본 `HOLD_MODE=duck`). 클라이언트는 재생을 멈추지 않고 출력 이득을 boost×gain으로 20 ms 램프로 낮춘다. 재생이 이어지므로 `playback` pos_ms 보고도 계속하고, 서버도 그 사이 문장·오디오를 계속 보낸다. `resume`이면 원래 이득으로 20 ms 램프 복귀, `interrupt`면 기존대로 중단(이득도 복귀). `mode`가 없거나 `pause`면 위의 일시정지 동작.
- `{"type":"resume","generation":g}` 보관한 위치부터 이어서 재생(덕킹이면 이득 복귀). g가 현재 generation과 다르면 무시.
- `interrupt`(새 generation 통지)는 hold로 보관한 오디오까지 모두 버린다.

### 마이크 프레임 복구 사다리 (클라이언트, 2026-11-03 v44 / app 0.6.2)

대화 시작 뒤 1.5초 안에 워클릿 pcm 프레임이 없으면(또는 대화 중 보내야 할 때 10초 넘게 없으면) `fixMic`이 순서대로 시도한다. 진단은 모두 `diag`로 서버 로그에 남는다.

1. 컨텍스트 재개(`resume`, 안 되면 `recoverContext`) + 캡처 그래프 재구성 → `[mic] 프레임 복구됨(그래프 재구성)`
2. 트랙을 버리고 `getUserMedia` 다시 → `[mic] 프레임 복구됨(트랙 재획득)`
3. 새 트랙에도 1.5초 안에 **레벨 보고(빈 입력 포함)조차 없으면** 컨텍스트 렌더링이 멈춘 것으로 보고(iOS: 끝내기 → 백그라운드 → 복귀 뒤 `ctx running`·`track live`인데 워클릿 `process()`가 안 불림, 2026-11-03 17:46 실기) **컨텍스트를 새로 만든다**: 옛 ctx `close()`(실패 무시) → 새 `AudioContext` → 재생 체인(outBus→analyser→outGain→limiter, earBus)·keep-alive 재생성 → `resume` → `audioWorklet.addModule` + 캡처 그래프 → 프레임 확인. 재생 큐(hold 보관분 포함)는 비운다. 로그 `[mic] 컨텍스트 재생성 #n (이유)`, 결과 `[mic] 프레임 복구됨(새 컨텍스트)` / `[mic] 새 컨텍스트도 프레임 없음`. 대화당 최대 2회, 그 뒤엔 상태줄 "마이크가 멈췄습니다. 앱을 닫았다 다시 여세요".
   - 새 컨텍스트가 1.5초 안에 running이 안 되면(제스처 밖에서 만들어 suspended) 상태줄 "구체를 한 번 더 눌러 주세요"를 띄우고, 다음 구체 탭 안에서 동기로 다시 만든다.
   - **바로 3단계**: `ctx.state`가 running인데 `currentTime`이 안 늘면 1·2단계를 건너뛴다(대화 시작 0.6초 뒤 검사, `fixMic` 시작 때 0.5초 측정, 2초 진단 줄의 증가분 0). 재생 중이거나 대화가 꺼졌으면 제외.
   - **복귀 점검**: `pageshow`/`visibilitychange`/`focus` 복귀 때 ctx가 running이면 `currentTime`을 300 ms 간격으로 두 번 재서 안 늘면 `[audio] 복귀 점검(...): ctx running인데 currentTime 정지`를 남기고 표시(`ctxStalled`)해, 다음 대화 시작(구체 탭, 제스처 안)에서 바로 새 컨텍스트를 만든다(`[mic] 컨텍스트 재생성 #n (대화 시작: 복귀 때 ct 정지)`). 대화 중이었으면 바로 3단계.

2초 진단 줄 `[mic] <dBFS> dBFS ctx <state> ct=+<초> track ... pcm <ms> 전 빈입력 <n> 송신 Y/N 재생 <n> ka on/off mute=... zeros=<초>s sysmute=<초>s[ 보류]`의 `zeros=`는 0 샘플 레벨 보고가 이어진 시간, `sysmute=`는 트랙 `muted=true`가 이어진 시간(`보류`는 시스템 음소거·중단으로 무음 판정 보류 중)이고, `ct=+2.000`은 지난 진단 이후 `ctx.currentTime` 증가분이다(첫 줄·컨텍스트가 바뀐 직후는 `ct=-`). running인데 `ct=+0.000`이면 멈춘 컨텍스트다. 콘솔 디버그 훅: `await hv.recreateContext()`는 3단계와 같은 경로로 컨텍스트를 새로 만들고 재생 체인·keep-alive·캡처 그래프가 새 ctx에 붙었는지 돌려준다.

### 출력 음량과 무음 버튼 (클라이언트, 2026-11-02)

iOS는 페이지가 마이크를 쥐고 있는 동안 오디오 세션을 통화형(재생+녹음)으로 바꿔 출력이 **통화 음량**을 따른다. 미디어 음량으로 내려면 들을 때만 마이크를 여는 방식이 필요한데 그러면 목소리 끼어들기가 불가능하다. ChatGPT 앱도 음성 모드에서 같은 통화형 세션을 쓴다. **사용자 결정: 통화형 세션 유지**(마이크 상시, 목소리 끼어들기). 스피커에서 소리가 작으면 이어폰을 권장한다.

대신 구체 양옆에 **무음 버튼 두 개**를 둔다. 왼쪽 마이크 끔: 마이크 트랙을 `enabled=false`로 두고 프레임을 보내지 않는다(트랙 stop은 하지 않아 권한·세션 유지). 오른쪽 소리 끔: 재생 체인 GainNode를 0으로 두어 타이밍·`playback` 보고·자막은 그대로, 소리만 없음(알림음도 끔). 둘 다 대화를 새로 시작하면 해제. 끼어들기는 목소리(서버 VAD)와 말하는 중 구체 탭(`interrupt`)뿐이다. 화면 아무 곳 탭은 자막 스크롤 오작동 때문에 두지 않는다('멈춤' 버튼은 구체 탭으로 대체).

### 서버 판정 규칙

- VAD: Silero VAD(ONNX, 16 kHz, 512샘플 창 32 ms). 말 시작 = 확률 ≥ 0.5가 연속 ≥ 160 ms. 말 끝 = 말 시작 뒤 확률 < 0.35가 연속 ≥ 700 ms(끝 침묵). 너무 짧은 발화(< 300 ms 음성)는 버린다. 발화 앞에 500 ms 프리롤을 붙여 STT에 넣는다. `conversation on`(Endpointer reset) 뒤 **첫 발화**만 프리롤을 1000 ms(`VAD_FIRST_PREROLL_MS`)로 늘린다(전송이 시작될 때 이미 말하는 중이어도 첫 음절이 남게). 사전 버퍼를 한꺼번에 받아도 창(32 ms) 단위로 판정하므로 결과는 같다.
- 끼어들기: 턴이 생각·말하는 중이거나 클라이언트가 재생 중일 때는 말 시작 기준을 올린다(확률 ≥ 0.7, 연속 ≥ 400 ms). 재생 중(또는 재생 직후 꼬리 구간)이면 먼저 `hold`로 잠정 판정하고(아래 '스피커 에코 대책'), 순수 생각 중이면 바로 generation을 올리고 TTS 큐·헤르메스 스트림을 끊고 `interrupt`를 보낸 뒤 그 발화를 계속 듣는다.
- STT 결과가 비었거나 환각 패턴이면 턴을 만들지 않고 `waiting`으로 돌아간다.
- `conversation off`를 받으면 서버는 진행 중인 턴과 재생을 끊고 `interrupt`를 보낸 뒤 `waiting`을 끝낸다.
- 받아쓰는 중(`transcribing`)에 말이 다시 시작되면 앞 발화를 새 발화 앞에 붙여 한 턴으로 처리한다.
- 답을 끝까지 못 듣고 끊긴 경우, 다음 발화 앞에 `(앞 답변은 사용자가 중간에 끊었음. 사용자가 들은 부분: "...")` 노트를 붙여 헤르메스에 보낸다. 헤르메스는 스트림이 끊겨도 진행 중인 LLM 호출을 끝까지 받아 전체 답을 세션에 남기기 때문이다. "들은 부분"은 `speak_start`로 보낸 문장 기준이라 실제 재생량보다 많을 수 있다.
- VAD 입력은 공식 구현처럼 직전 창 64샘플을 앞에 붙인 [1,576]이다.
- 끝 침묵 시간은 `VAD_END_SILENCE_MS`(기본 700), 시작 기준은 `VAD_START_MS`(160)·`VAD_THRESHOLD`(0.5), 끼어들기 기준은 `BARGE_THRESHOLD`(0.7)·`BARGE_MS`(400) 환경 변수로 조정. 추가 변수: `VAD_END_THRESHOLD`, `VAD_PREROLL_MS`(500), `VAD_FIRST_PREROLL_MS`(1000), `VAD_MIN_SPEECH_MS`, `VAD_MAX_UTTERANCE_MS`, `SILERO_VAD_MODEL`. (선택) `TURN_DETECTOR=smart-turn`이면 pipecat Smart Turn v3.2(ONNX, `models/`에 8 MB, numpy+onnxruntime만 사용)로 침묵 300 ms에 말 끝을 보조 판정한다(판정 약 70 ms, 전체 약 475 ms). 2026-11-02 실측에서 한국어 판정이 미덥지 않아(잘린 음성·1초 잡음도 '완료') **기본은 꺼 둠**.

## 스피커 에코 대책 (2026-11-02)

실기 진단: 아이폰 스피커로 TTS가 나가면 iOS AEC를 뚫고 에코가 마이크로 들어와 재생 중 끼어들기(0.7/400 ms)가 나고, 그 에코가 받아써져 사용자 발화로 헤르메스에 갔다(채움 말 "잠깐 확인해 볼게요."가 1.3초 뒤 끊기고 그대로 받아써짐). 대책은 아홉 가지다.

1. **잠정 끼어들기(hold/resume)**. 재생 중(클라이언트 `playback`이 speaking이거나 서버가 문장을 합성·전송 중) 또는 재생 직후 꼬리 구간에서 생각 중일 때 VAD 시작이 끼어들기 기준을 넘으면 generation을 올리지 않고 `hold`를 보내고 hold 상태가 된다(state `listening`). 서버 스피커 태스크는 hold 동안 `speak_start`·오디오·`speak_end`를 보내지 않고 기다린다(헤르메스 스트림은 계속 받음. `HOLD_MODE=pause`일 때. v19 기본 `duck`은 7번: 재생·전송을 계속하고 소리만 낮춘다). 그 뒤:
   - hold 뒤 음성 창(확률 ≥ 0.35인 32 ms 창) 누적이 `HOLD_CONFIRM_MS`(900) 넘게 이어지면 진짜 말로 확정: `interrupt`(generation+1, 끊긴 답 노트) 후 발화를 계속 듣고 말 끝에서 평소처럼 STT → 턴. (재생이 멈추면 에코도 멈추므로 에코는 보통 여기까지 못 간다. 침묵 창은 세지 않는다.)
   - 그 전에 짧은 소리(`discard`)로 끝나면 `resume`.
   - 그 전에 말 끝이면 받아쓰기(`transcribing`) → 비었거나 에코면 `resume`하고 조용히 버림(`transcript` 안 보냄, 로그 `에코 무시: ...`). 진짜 말이면 `interrupt` → `transcript` → 받아쓴 글로 바로 생각 단계(다시 받아쓰지 않음).
   - 판정 중 말이 다시 시작되면 앞 발화를 붙여 hold를 이어 간다.
   - 재생도 꼬리 구간도 아닌 순수 생각 중의 끼어들기는 예전처럼 즉시 `interrupt`.
2. **에코 필터** (`server/echo.py`). `speak_start`로 보낸 문장(채움 말 포함)을 `ECHO_MEMORY_S`(v22부터 60초, 문장 추정 재생 종료부터, 9번) 동안 기억한다. 받아쓴 문장과 기억한 문장을 공백·문장부호 제거·소문자로 정규화해, 정규화 길이 ≥ 2이고 (최근 문장 연결 문자열의 부분 문자열 / `difflib.SequenceMatcher` 비율 ≥ 0.75인 문장이 있음 / 문자 bigram의 70% 이상이 최근 문장에 있음) 중 하나면 에코. 적용 대상: hold 판정, 재생 중 또는 재생 끝(`playback idle`/`speak_end` 추정) 뒤 `ECHO_TAIL_MS` 안에 시작된 발화(확정 끼어들기 뒤 발화 포함). 에코면 `transcript` 없이 rest 상태로 돌아간다. "네" 같은 한 글자 답은 에코로 보지 않는다.
3. **끼어들기 기준 판단 정확화**. 엄격 기준(0.7/400 ms)은 "턴이 생각·말하는 중(받아쓰는 중 제외)이거나, 보낼 문장이 큐에 남았거나, 재생 중"일 때만. stale한 state는 보지 않는다. 재생 중 판단은 `playback speaking`이되, idle을 못 받아도 보낸 오디오 길이로 추정한 재생 끝 + 3초가 지나면 재생 아님으로 본다(끊긴 답 노트 오작동 방지도 같은 기준). 서버는 오디오를 실시간보다 빨리 보내므로 '문장 사이 600 ms 유예'는 **추정 재생 끝 + 600 ms**로 잰다: 그때까지 다음 문장이 없고 턴이 진행 중이면 `thinking`, 다음 문장이 오면 다시 `speaking`.
4. **꼬리 가드**. `playback idle`(현재 generation) 또는 `speak_end`(추정 재생 끝 기준) 뒤 `ECHO_TAIL_MS`(1500) 동안 Endpointer의 시작 확률을 `VAD_TAIL_THRESHOLD`(0.6)로 올린다(시간은 일반 `VAD_START_MS`, barge 아님. `Endpointer(tail=...)`/`set_tail()`). 이 구간에 시작된 발화는 받아쓴 뒤 에코 필터를 거친다.
5. **TTS 라우드니스 정규화** (`server/tts.py`). 합성 결과마다 음성 구간(32 ms 프레임 RMS > -40 dBFS) RMS를 `TTS_TARGET_RMS_DB`(-18)에 맞추는 이득을 주되 피크가 `TTS_PEAK_DB`(-1) 이하가 되게 제한, int16 클리핑. 알림음(클라이언트)은 그대로. 실측(F1, 2026-11-02): 원래 음성 RMS -22.8~-24.4 dBFS, 피크 -5~-11 → 정규화 뒤 RMS -18.1~-18.2, 피크 -2.5~-4.5(이득 +4.7~+6.3 dB). 전후 레벨은 `tts` 로거 DEBUG.

6. **에코 대조 감지기** (`server/aec_gate.py`, 2026-11-02 v18). 받아쓰기 **전에** 마이크 소리가 내 TTS의 에코인지 가린다. 실기 로그에서 답변 중 약 2초마다 hold → 1초 뒤 '에코 무시' → resume이 반복돼 "말하다 끊기다"로 들린 문제의 대책.
   - **참조 신호**: 서버가 보내는 TTS PCM(44.1 kHz)을 generation별로 16 kHz로 내려(`scipy.signal.resample_poly(…,160,441)`, 없으면 numpy 저역+보간) 이어 붙인다(위치 0 = 그 generation 첫 샘플, 상한 5분, generation이 바뀌면 비움). 16 ms 격자·32 ms 창 RMS 포락선(dB, 하한 -70)을 미리 계산.
   - **재생 시간축**: `playback`의 `pos_ms - out_latency_ms`와 도착 시각으로 `pos(t) = pos_last + (t - t_last)·1000`. hold·idle·interrupt 시각 뒤는 스피커 무음, resume 시각 + 60 ms부터 멈춘 위치로 이어서(다음 보고가 바로잡음). `pos_ms`를 한 번도 안 보낸 클라이언트는 감지기를 끄고 기존 `_play_until` 추정만 쓴다.
   - **판정**(마이크 32 ms 창마다, 재생 중 또는 재생이 멈춘 뒤 1초 안에만 상관 계산): 최근 W=20창(640 ms) 마이크 RMS 포락선(dB)과, 같은 시각들 − lag에 스피커에서 나오던 참조 포락선을 lag ∈ [-100, +600] ms(16 ms 간격)로 비교한 피어슨 상관. 20창으로는 독립 음성도 lag 44개 중 최대 상관이 우연히 높게 나오므로(합성 실측 중앙값 0.75) **lag를 추적**한다: lag별 상관을 느린 EMA(α 0.08)로 쌓아 그 최대 lag ±1칸의 상관만 쓴다. 참조 포락선 최대가 -50 dBFS 미만이면 판정 보류(에코 아님). 상관 ≥ `ECHO_CORR`(0.6)이면 **에코 우세**.
   - **에코 바닥(사용자 말 섞임 해제)**: 에코 우세 창에서 (마이크 dB − 참조 dB)를 느린 EMA(α 0.03)로 추적한 에코 이득으로 창별 추정 에코 레벨 `floor_db = max(참조 dB(±1창 최대) + 이득, 마이크 잡음 바닥)`을 만든다. 최근 10창(320 ms) 중 2창 이상에서 마이크가 `floor_db + ECHO_MARGIN_DB`(8) 이상이면 사용자 말이 섞인 것으로 보고 480 ms 동안 에코 우세를 내지 않는다. (설계안의 '에코 우세 창 마이크 RMS의 EMA 하나'는 음절 크기 변화·참조 쉼 구간 때문에 순수 에코도 자주 넘거나, 쉼에 끼어든 말을 놓쳐서 참조 레벨에 맞춰 움직이는 바닥으로 바꿈.) 합성 실측: 순수 에코(200 ms 지연, -20 dB, 저역·클리핑) 에코 우세 ~100%, lag 추정 188~204 ms; 에코보다 6 dB 큰 독립 음성이 섞이면 에코 우세 0~27%, 비에코 연속 ≥ 53창.
   - **(v22) 레벨 규칙 전역 적용**: 아래 예측 레벨 규칙을 문장 시작 보호 구간 밖에도 적용한다(`mic_db ≤ expected_db + ECHO_MARGIN_DB`, 보호 구간 안은 +4 dB). 실기(19:55): 문장 중간 corr 0.45로 -51 dBFS 에코에 덕킹 hold가 걸렸고, 실제 끼어들기는 -30.5 dBFS로 에코(-44~-51)보다 12 dB 넘게 컸다. 상관은 참조 포락선 표준편차가 3 dB 이상인 lag에서만 계산(평평한 참조에서 우연한 상관으로 이득이 잘못 학습되는 것 방지).
   - **예측 레벨 게이트(문장 시작 보호, v19)**: 참조가 `ONSET_SILENCE_MS`(160) 넘게 무음이다가 유음으로 바뀐 뒤 `ONSET_GUARD_MS`(400) 동안만, 창마다 예상 에코 레벨 `expected_db = max(참조 dB at pos(t − lag_est) ±64 ms) + gain_est`(lag_est 초기 90 ms, gain_est 초기 −22 dB, 둘 다 상관으로 에코가 확인된 창에서만 느리게 학습)를 계산해 `mic_db ≤ expected_db + ECHO_MARGIN_DB + 4`이면 상관 이력과 무관하게 에코 우세. 640 ms 이력이 무음이라 상관이 무의미한 문장 시작 직후 hold(실기 19:04~06: corr 0.03~0.79, mic −44 dBFS, 받아쓰기는 전부 에코)를 막는다. 보호 구간 밖에서는 레벨을 쓰지 않는다(사용자 말도 에코 수준으로 눌려 들어오므로, 상관 + 7번 덕킹 검사가 판정). 보호 구간에서 예상 + 여유를 넘는 창이 최근 10창 중 2개 이상이면 480 ms 해제.
   - **절대 최소 음량**: strict 시작 카운터와 hold 확정 카운터는 창 RMS ≥ `BARGE_MIN_DB`(−52, 사실상 잡음만 거름)인 창만 센다. 그 아래 창은 세지 않되 연속을 끊지 않는다.

## 실측 (2026-11-02, 0단계 e2e, 실제 헤르메스)

- STT 2.9초 음성 → 322 ms. TTS 문장당 280~510 ms(CPU, RTF 0.12~0.14). 50자 넘는 문장 약 1.1초.
- 말 끝 → 첫 오디오 4.2초(날씨 질문, 도구 3개 사용, "잠깐 확인해 볼게요."가 먼저 나옴).
- 헤르메스 첫 토큰: voice-fast 2.1초(프롬프트 캐시 적중)~8.7초(미적중, 프롬프트 약 3만 7천 토큰), voice-deep 3.4초. 지연의 대부분은 헤르메스의 큰 시스템 프롬프트.
- SSE: OpenAI `chat.completion.chunk` + 이름 있는 이벤트 `hermes.tool.progress`(`{"tool","emoji","label","toolCallId","status":"running"|"completed"}`). 처음 쓰는 `X-Hermes-Session-Id`도 바로 세션이 되고 다음 요청에서 기억한다.
