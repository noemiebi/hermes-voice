# Hermes Voice 설계

아이폰 홈 화면 웹앱(PWA)에서 Hermes Agent와 말로 대화하는 로컬 음성 서버의 설계 문서다. 메시지 형식과 세부 판정 값은 [`프로토콜.md`](프로토콜.md), 설치와 환경 변수는 [`README.md`](../README.md)를 본다.

## 1. 목표와 원칙

- **자연스러운 음성 대화.** 짧은 응답 지연, 말 끊기(barge-in), 답을 문장 단위로 바로 읽어 주기를 목표로 한다.
- **음성 처리는 전부 로컬.** STT와 TTS는 Apple Silicon 맥 안에서 돈다. OpenAI Realtime, ElevenLabs, Deepgram, 클라우드 TTS 같은 외부 음성 API는 쓰지 않는다.
- **두뇌는 Hermes Agent 하나.** 음성 전용 모델을 따로 두지 않는다. Hermes API 서버에 음성 세션을 열어 다른 채널과 같은 기억·도구·성격을 그대로 쓴다. Hermes 본체는 고치지 않고 설정(API 서버 켜기, 모델 라우트 추가)만 한다.
- **문장 단위 합성.** 답 전체를 기다리지 않고 첫 문장이 완성되는 즉시 합성해 보낸다. 뒷문장은 앞 문장이 재생되는 동안 합성한다.
- **끼어들기.** 답을 듣는 중에 말하면 재생과 생성을 멈추고 새 말을 다음 턴으로 받는다.
- **1인용 설계.** Hermes 세션과 대화 기록이 서버 전체에 하나다. 여러 사람이 접속하면 같은 대화를 공유한다.

## 2. 구성

```
아이폰 PWA ──WebSocket(PCM 16 kHz + JSON 이벤트)──▶ 음성 서버(FastAPI, Python)
  마이크 AudioWorklet                                ├─ VAD: Silero VAD(ONNX) 말 시작·끝
  재생: AudioBufferSourceNode 큐 + 이득·리미터        ├─ 말 끝 보조: Smart Turn v3(선택)
  자막(내 말·답), 상태 링, 설정                       ├─ STT: mlx-whisper large-v3-turbo 상주
                                                    ├─ 두뇌: Hermes API 서버 /v1/chat/completions (SSE)
                                                    │     모델 라우트 voice-fast / voice-deep
                                                    ├─ 문장 분할기 → 독음 정규화 → TTS 상주
                                                    │     Qwen3-TTS(기본) / Supertonic 3(폴백·가벼운 대안)
                                                    ├─ 에코 판정: 에코 대조 게이트, 덕킹 검사, 텍스트 필터
                                                    └─ 대화 기록 보존(history.json)
```

- **모델 라우트.** 음성 서버는 Hermes에 `voice-fast`(기본, 빠른 응답)와 `voice-deep`(깊게 생각) 두 라우트 이름으로 요청한다. 각 라우트가 어떤 모델·공급자로 가는지는 각자 Hermes 설정에서 정한다. `voice-fast` 요청에는 추론을 끄는 옵션을 붙일 수 있다.
- **접속 경로.** 브라우저 마이크는 HTTPS에서만 열리므로 서버는 루프백에 바인드하고 Tailscale `serve` 같은 사설망 HTTPS로 연다. 공개망에 열 때는 접속 토큰을 쓴다.
- **상주.** STT·TTS·VAD 모델은 서버 시작 때 한 번 올려 두고, mlx·ONNX 호출은 각각 단일 워커 스레드에서만 한다. Qwen3-TTS는 의존성 충돌 때문에 별도 가상환경의 서브프로세스로 돌린다.

## 3. 턴 파이프라인

1. **VAD.** 클라이언트는 대화 중 16 kHz PCM을 약 100 ms 단위로 계속 보낸다. 서버의 Silero VAD가 32 ms 창마다 말소리 확률을 내고, 기준을 일정 시간 연속으로 넘으면 말 시작으로 본다. 말 시작 앞 수백 ms(프리롤)를 붙여 첫 음절이 잘리지 않게 한다.
2. **말 끝 판정.** 기본은 끝 침묵(약 0.7초)이다. 선택으로 Smart Turn v3를 켜면 짧은 침묵에서 "말이 끝났는지"를 모델에 묻고, 완료면 바로 말 끝으로, 아니면 침묵 기준까지 기다린다.
3. **STT.** 모은 발화를 mlx-whisper로 받아쓴다. 빈 결과와 환각(자막·뉴스류 상용구, 길이 대비 글자 수 과다, 높은 압축률)은 버린다. 받아쓰는 동안 말이 다시 시작되면 앞 발화를 새 발화 앞에 붙여 한 턴으로 처리한다.
4. **Hermes SSE.** 받아쓴 글을 현재 라우트로 스트리밍 요청한다. 음성용 지시(짧은 구어체, 마크다운·목록·URL 금지, 도구 결과를 확인하기 전에 성공했다고 말하지 않기)를 붙인다. 첫 문장 전에 도구 시작 이벤트가 오면 "잠깐 확인해 볼게요." 같은 채움 말을 턴당 한 번 먼저 읽는다.
5. **문장 분할.** 토큰을 스트리밍 문장 분할기에 넣어 문장이 완성될 때마다 TTS 큐로 보낸다. 마크다운·기호는 지우고, 합성 직전에 영어 단어·약어·숫자 표기·기호를 한국어 독음으로 바꾼다. 화면 자막은 원문 그대로다.
6. **TTS.** 문장마다 합성하고 음성 구간 RMS를 일정 목표로 맞추는 라우드니스 정규화를 거친 뒤 PCM 청크로 보낸다. 기본 엔진은 Qwen3-TTS(스트리밍)이고, 실패하거나 첫 청크가 늦으면 그 문장은 Supertonic으로 폴백한다(Supertonic 모델이 없으면 Qwen을 기다린다).
7. **재생.** 클라이언트는 받은 청크를 이어서 재생하고, 재생 상태와 실제 재생 위치(`pos_ms`)를 주기적으로 서버에 알린다. 서버는 이 보고로 "지금 내 목소리가 스피커에서 나오는 중인지"를 안다.

모든 턴은 `generation` 번호를 갖는다. 끼어들기가 확정되면 번호를 올리고, 옛 번호의 오디오는 서버·클라이언트 모두 버린다.

## 4. 상태 기계

| 상태 | 뜻 |
|---|---|
| `idle` | 대화가 꺼져 있음 |
| `waiting` | 핸즈프리 대화 중, 말을 기다림 |
| `listening` | 말하는 중(또는 잠정 끼어들기 판정 중) |
| `transcribing` | 받아쓰는 중 |
| `thinking` | Hermes 응답을 기다리거나 다음 문장을 합성하는 중 |
| `speaking` | 답을 재생하는 중 |

기본 흐름은 waiting → listening → transcribing → thinking → speaking → waiting이다. 다음 문장이 늦으면 speaking과 thinking을 오가고, 잠정 끼어들기 중에는 speaking → listening → speaking(에코로 판정해 복귀) 또는 → listening/thinking(끼어들기 확정)으로 간다. 채움 말을 다 읽고 큐가 비면 thinking으로 돌아가 엄격한 끼어들기 기준이 계속 걸리지 않게 한다.

## 5. 끼어들기와 에코 처리

스피커로 나간 답이 마이크로 되돌아오면 사용자 말로 오인된다. iOS의 에코 캔슬(AEC)은 이를 완전히 막지 못한다. 대책은 여러 겹이다.

- **엄격한 시작 기준.** 생각·말하는 중이거나 재생 중이면 말 시작 기준(확률·연속 시간)을 높인다. 재생 끝 직후 짧은 꼬리 구간에도 기준을 올리고, 그 구간 발화는 에코 필터를 거친다.
- **잠정 끼어들기(hold).** 재생 중 말소리가 잡히면 곧바로 끊지 않고 hold로 판정을 미룬다. 판정 결과에 따라 `resume`(에코였음)이나 `interrupt`(진짜 말)를 보낸다. 순수 생각 중의 끼어들기는 즉시 `interrupt`다.
- **덕킹 검사(기본).** hold 때 재생을 멈추지 않고 출력 이득만 크게 낮춘다. 마이크 레벨이 따라 내려가면 내 소리의 에코이므로 원래 이득으로 복귀하고, 내려가지 않으면 사용자 말로 확정한다. iOS는 재생 중 사용자 음성도 강하게 눌러 에코와 레벨이 비슷하게 들어오므로, 레벨 비교보다 "내 소리를 줄였을 때 반응하는가"가 더 믿을 만하다.
- **AEC 게이트(에코 대조 감지기).** 서버가 보낸 TTS PCM을 참조 신호로 두고, 클라이언트의 재생 위치 보고로 시간축을 맞춰 마이크 RMS 포락선과 참조 포락선의 상관·예상 에코 레벨을 창마다 비교한다. 에코 우세 창은 끼어들기 카운트에서 빼고, 에코 비율이 높은 발화는 받아쓰기 없이 버린다.
- **텍스트 에코 필터.** 받아쓴 문장이 최근 읽어 준 문장과 같은 말(부분 문자열, 유사도, 문자 bigram 포함률)이면 버린다.
- **half-duplex 옵션.** 에코 캔슬이 안 되는 환경을 위해, 켜면 재생 중에는 마이크 프레임을 보내지 않는다. 대신 목소리로 끼어들 수 없다.
- **끊긴 답의 맥락.** Hermes는 스트림이 끊겨도 답 전체를 세션에 남긴다. 그래서 다음 발화 앞에 "앞 답변은 중간에 끊겼고, 들은 부분은 여기까지"라는 노트를 붙여 맥락을 맞춘다.

## 6. 주요 설계 결정

- **VAD를 서버에서 한다.** 판정 값과 에코 대책을 한곳에서 고치고 로그로 검증할 수 있고, 에코 판정에 필요한 참조 신호(보낸 TTS)도 서버에 있다. 클라이언트는 PCM과 재생 상태만 보내는 얇은 구조가 된다.
- **재생 판단은 클라이언트 보고를 따른다.** 서버는 오디오를 실시간보다 빨리 보내므로 전송량으로 추정한 재생 끝은 실제보다 훨씬 이르다. 클라이언트가 보고한 재생 위치를 기준으로 삼는다.
- **대화 기록의 정본은 서버에 둔다.** iOS 홈 화면 앱은 다시 열 때 localStorage가 사라지는 경우가 있다. 서버가 화면 기록과 마지막 세션을 JSON 파일 하나에 보존하고, 접속 때 클라이언트에 돌려준다. 세션은 이어 쓰며, 새 대화는 사용자가 `+`로 직접 시작한다(유휴 시간 뒤 자동 교체는 옵션, 기본 꺼짐). 대화가 켜져 있는 동안에는 세션을 바꾸지 않는다.
- **keep-alive 신호.** iOS는 출력이 무음이 되면 오디오 세션을 재구성하며 마이크 캡처를 몇 초간 완전 무음으로 만드는 일이 있다. 대화 중에는 들리지 않을 만큼 작은 상수 신호를 출력에 흘려 무음 판정을 막는다(설정으로 끌 수 있다). 그래도 입력이 일정 시간 정확히 0이면 트랙을 다시 받는다.
- **마이크 트랙을 멈추지 않는다.** 홈 화면 앱은 실행할 때마다 마이크 권한을 다시 물을 수 있어, 실행 중에는 트랙을 stop하지 않고 `enabled`로만 끈다.
- **통화형 오디오 세션을 받아들인다.** 마이크를 쥐고 있으면 iOS가 출력을 통화 음량으로 바꾼다. 목소리 끼어들기를 위해 마이크를 상시 열어 두는 쪽을 택하고, TTS 라우드니스 정규화와 앱 안의 소리 크기 설정(리미터 포함)으로 보완한다. 스피커에서는 이어폰이 가장 안정적이다.
- **포그라운드 복귀 처리.** iOS는 홈 화면 앱을 다시 열 때 페이지를 새로 로드하는 경우가 있다. 복귀 때 AudioContext·마이크 트랙·WebSocket을 복구하고, 서버 기록으로 화면을 다시 그린다. 에코 캔슬 설정을 바꿀 때도 트랙 재획득 대신 페이지를 다시 연다(재획득이 죽은 트랙을 주는 경우가 있다).
- **도구 사용 즉시 채움 말.** 도구를 쓰는 답은 첫 문장이 늦다. 도구 시작 이벤트에 맞춰 짧은 말을 먼저 읽어 침묵을 줄인다.
- **Hermes 쪽 지연 줄이기.** 첫 토큰 지연의 대부분은 시스템 프롬프트(도구·스킬 설명) 크기와 모델 추론에서 온다. API 서버 플랫폼에 붙는 도구를 음성에 필요한 것으로 줄이고, `voice-fast`에서 추론을 끄면 첫 토큰이 크게 줄어든다.
- **프레임워크 대신 얇은 서버.** pipecat 같은 프레임워크를 통째로 쓰지 않고 Hermes API에 맞춘 작은 서버로 구성한다. Smart Turn 같은 부품만 가져온다.
- **음성-음성 통합 모델은 보류.** 한국어 실시간 대화와 맥 로컬 실행 경로가 아직 성숙하지 않았다.
- **STT 어휘 프롬프트는 기본으로 비운다.** 깨끗한 음성에서 오히려 오류율을 높였다.

## 7. 알려진 한계

- **백그라운드 동작 불가.** 화면을 떠나면 WebKit이 마이크 캡처를 멈춘다. Dynamic Island 표시(Live Activity)도 네이티브만 가능하다. 둘 다 네이티브 래퍼 앱이 필요하다.
- **스피커 모드 에코.** 여러 겹의 대책에도 스피커 재생 중 오판이 남을 수 있다. 이어폰이나 half-duplex가 가장 확실하다.
- **출력 음량.** 통화 음량 규칙은 웹에서 피할 수 없다. 에코 캔슬을 끄면 소리가 수화부로 나와 더 작아진다.
- **응답 지연은 Hermes가 좌우한다.** 로컬 음성 처리(VAD·STT·TTS 첫 청크)는 1초 안쪽이지만, 말 끝부터 첫 소리까지 걸리는 시간의 대부분은 Hermes 첫 토큰이다. 공급자 응답 시간에 따라 크게 흔들린다. 답을 통째로 돌려주는(스트리밍하지 않는) 경로를 쓰면 채움 말과 첫 문장이 늦어진다.
- **Smart Turn의 한국어 판정.** 한국어 말 끝 판정이 충분히 미덥지 않아 기본은 끝 침묵만 쓴다.
- **"들은 부분" 근사.** 끊긴 답의 "들은 부분"은 보낸 문장 기준이라 실제로 들은 양보다 많을 수 있다.
- **iOS 레이아웃.** 일부 iOS 버전에서 홈 화면 앱 아래쪽에 웹 뷰 바깥 빈 띠가 생긴다. 배경색으로 가릴 뿐 우회책은 없다.
- **1인용.** 인증은 선택적 접속 토큰 하나이고, 세션·기록이 사용자별로 나뉘지 않는다.
